# Dialectio

Web app: enter a word → see on a map how it is written, pronounced (IPA) and sounds in different languages and dialects.
Full plan and decisions: [docs/plan.md](docs/plan.md). Communicate with the user in Ukrainian.

## Layout
- `backend/` — FastAPI (Python 3.11+, managed with uv), SQLAlchemy + Alembic, PostgreSQL/PostGIS
- `frontend/` — Next.js (TypeScript) + MapLibre GL, i18n (uk, en)
- `backend/app/importers/` — import scripts for open data (run as `uv run python -m app.importers.<name>`); downloads go to git-ignored `data/raw/`
- `docs/` — plan and design notes

## Conventions
- Data is organized around `Concept` (meaning), not raw word strings.
- Varieties are identified by `Variety.code`: ISO 639-3 for languages, `<language>-<name>` for dialects (`ukr-hutsul`). Dialect territories are oblasts (`app/importers/dialects.py`); the map shows oblast labels instead of the country label from zoom 5.
- First-level regions exist for Ukraine and its neighbours with Ukrainian dialects (PL, SK, RO) for Western Europe (DE, AT, CH, NL, BE, FR, IT, ES, GB, England split into its 9 regions) the US states and Canada's provinces; small Natural Earth units are merged into the regions of `app/importers/data/regions.json` (Brittany, Sicily, Wales, North West England ...; regions dropped from the file are deleted on import). Regional languages (Welsh, Breton, Sicilian, Low German ...) are languages mapped to these regions in `app/importers/languages.py`. Rusyn is deliberately not added (it overlaps the Transcarpathian dialect; politically sensitive).
- Dialect words are compared with their own language's standard word (`split_part(code, '-', 1)`: ukr-hutsul → ukr, deu-bavarian → deu). After re-running `wikidata_lexemes`, always run the rest of the import chain in order (descriptions, glosses, wiktionary, localize, definitions, tts): skipping `glosses` leaves Wikidata labels like "Erinaceinae"; new duplicate concepts go into `data/excluded_concepts.txt`.
- What a visitor sees first follows the interface language (`frontend/src/lib/visitor.ts`): the home page's word of the day and examples, the map area and the default check-game deck are the regional words of their language (uk/pl → Ukrainian dialects, de → German areas, en → US/Britain, es → Spanish by country, fr → French); "where do you live?" puts the browser language's country first (de-AT → Austria). No IP geolocation. Each language's deck includes its dialect areas.
- The community is meant to be international: "where do you live?" offers every region and every other country, community features must not assume Ukrainian visitors.
- Every imported record must keep its `Source` (name, url, license).
- Synthetic (TTS) audio must be flagged `is_synthetic`.
- Forms have `status`: `approved` or `pending` (drafts from `app.importers.suggestions`, source "Dialectio suggestions (draft)"). Both are public (`PUBLIC_STATUSES`); drafts are marked unverified ("≈") until approved in the editor. Public queries must filter on `PUBLIC_STATUSES`.
- Visitors check words with anonymous votes (`vote`) and error reports (`report`), see `app/api/feedback.py`. Votes never change a word: enough yes-weight gives the "👥 confirmed by speakers" mark (`community_status` in `app/models/feedback.py`, totals in `app/api/votes.py`), which stays below an editor's approval; editors see votes and reports in the editor ("Голоси й помилки").
- Votes are weighted (`vote.weight`, set when cast): a guest counts `GUEST_WEIGHT` (0.25) only after passing the quiz of the word's language, else 0. The quiz and the game use control cards (`app/api/gold.py`): a checked word with its own meaning ("yes") or a real word with another concept's meaning (a trap, "no"); the token hides the answer (HMAC with `SECRET_KEY`), each token counts once; passed = 2 of the last 3 control answers in the language right, a failure waits a day. Members (`app_user`, `app/api/accounts.py`: email + password hashed with scrypt, HttpOnly session cookie `dialectio_session`, CORS with credentials; "Sign in with Google" in `app/api/google_auth.py`, OAuth client of the Google Cloud project on dialectio.team@gmail.com, keys `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` in `.env`, redirect URI `<API_URL>/api/auth/google/callback`; a Google sign-in sets `email_verified_at` and drops the password of an account whose email was never proven; email links planned) vote and answer as "user:<id>" from any browser and count `MEMBER_WEIGHT` (0.5) after the quiz; frontend requests that need the member send `credentials: "include"`, the member is in `useAccount()` (`components/Account.tsx`). The frontend asks via `useQuizGate()` (`components/QuizGate.tsx`) before a guest's first vote on a language. Plan for accounts and trust levels: docs/plan.md.
- Word search matches `search_key(spelling)` (SQL function from the migrations: no accents via `unaccent`, Cyrillic romanized), so "Worterbuch" finds "Wörterbuch" and "kartoplia" finds "картопля"; the trigram index is on that expression
- Only one uvicorn may listen on port 8000: an orphaned old server keeps serving stale code. If changes don't show up, check `Get-NetTCPConnection -LocalPort 8000` and stop stray processes.
- Concept slugs (`/[locale]/word/[slug]`) are permanent once assigned (`app/slugs.py`); never recompute them, URLs are indexed by search engines.
- Use only free/open data sources and libraries; no Google Maps.
- UI strings live in `frontend/messages/{uk,en,pl,de,es,fr}.json` (the editor section stays English in pl/de/es/fr); names of concepts, languages and regions in pl/de/es/fr come from the JSON `names` / `glosses` / `descriptions` columns (`app/locales.py`), picked with `localized(locale, en, uk, names)` (next-intl); routes are prefixed with the locale (`/uk`, `/en`), default `uk`. Never hardcode UI text in components.
- Do not `git push` without discussing with the user first.

## Commands
- Start DB: `docker compose up -d db`
- The dev database listens on 127.0.0.1 only (its password is public); connect via `127.0.0.1`, not `localhost`: on Windows `localhost` tries IPv6 first and each connection waits ~30 s
- Analytics (optional): `docker compose --profile analytics up -d umami` → http://localhost:3001 (Umami, its own `umami` database); the site sends page views only when `NEXT_PUBLIC_UMAMI_SRC` and `NEXT_PUBLIC_UMAMI_WEBSITE_ID` are set in `frontend/.env.local`
- Backend (from `backend/`): `uv sync`, `uv run uvicorn app.main:app --reload`, `uv run pytest`, `uv run ruff check .`
- Data import order (from `backend/`, all re-runnable): `natural_earth` (countries) → `natural_earth_admin1` (oblasts) → `wikidata_lexemes` → `descriptions` (our Ukrainian descriptions where Wikidata has none) → `glosses` (our concept names in `data/glosses.json`, keyed by Wikidata item or, for Wiktionary concepts, by slug; they win over Wikidata labels and Wiktionary's first translation, homonyms get a hint in brackets) → `wiktionary` (translation tables of the words in `data/extra_words_en.txt` (concepts regional words need: apricot, doughnut, hello ...) and the 5 000 most frequent English words from English Wiktionary via kaikki.org, ~3.3 GB download to `data/raw/wiktionary/`; run with `uv run --group import ...` so wordfreq can push rare translations back) → `dialects` → `localize` (names in the extra UI languages pl/de/es/fr: concept names from each language's main word, CLDR language names, Natural Earth region names, `data/dialect_names.json`; run last and after any import, `uv run --group import ...`) → `definitions` (descriptions in pl/de/es/fr where Wikidata has none: the meaning's definition from that language's Wiktionary via kaikki.org, ~1.3 GB to `data/raw/wiktionary/`, else an Argos Translate machine translation of the English one, run through `uvx` because Argos pulls in torch; `Concept.description_origins` marks them `wiktionary` / `machine` and the site labels them; no Ukrainian machine translations, they are too poor) → `grinchenko` (dialect drafts from Hrinchenko's dictionary on uk.wikisource: entries recorded in one dialect's area only, tied to a concept through the Russian definition; `--sample N` prints candidates; `uv run --group import ...`) → `regional_words` (other languages' dialect areas, German, Italian, English (US / Britain), Spanish (by country), French (France / Belgium / Switzerland / Quebec): `data/regional_words_<lang>.json` = {concept slug: {area code: word}} plus `"_main"` = {slug: the language's standard word} where Wiktionary's first translation is odd; drafts; areas are dialects `deu-*`, `ita-*`, `eng-us-*`, `eng-uk-*`, `spa-*`, `fra-*` in `dialects.py`, mapped to regions or, for Spanish, to whole countries) → `suggestions` / `suggestions --machine` → `tts`, each as `uv run python -m app.importers.<name>`; restart the API after region imports (vector tiles are cached in memory)
- Machine words (from `backend/`): `uv run python -m app.importers.suggestions --machine <iso> ...` loads `data/machine/<iso>.json`; real Wikidata data replaces them on the next import
- Word editor: `/uk/editor`, token = `EDITOR_TOKEN` in `.env`; editor words use source "Dialectio editors" and survive Wikidata re-imports
- Import words (from `backend/`, after countries): `uv run python -m app.importers.wikidata_lexemes` (~10 min, re-runnable); word lists and exclusions live in `backend/app/importers/data/`
- TTS (from `backend/`): `uv tool install piper-tts` once, then `uv run python -m app.importers.tts [iso ...]` after every Wikidata import and after approving words (only approved primary words without recordings get synthetic audio). Piper is GPL: run it only as an external program, never import it. Only voices whose license allows commercial use go into `VOICES`.
- Migrations (from `backend/`): `uv run alembic revision --autogenerate -m "..."`, `uv run alembic upgrade head`
- Frontend (from `frontend/`): `npm install`, `npm run dev`, `npm run lint`, `npm run build`
- `uvicorn --reload` on Windows sometimes misses file changes: if the API serves old code, restart it
- Production: `docker-compose.prod.yml` (db, backend, frontend, umami, Caddy) with `.env.prod`; full steps in [docs/deploy.md](docs/deploy.md). Pages that fetch the API outside a dynamic route call `await connection()` so `next build` (in Docker, without the API) does not prerender them
- Next.js 16 has breaking changes vs older versions: check `frontend/node_modules/next/dist/docs/` before writing frontend code.
